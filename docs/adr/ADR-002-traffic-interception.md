# ADR-002: Двухслойный перехват трафика и сменный Redirector

**Статус:** ⚠️ Частично заменён [ADR-007](ADR-007-adaptive-interception.md)

> **Что осталось в силе:** двухслойная модель перехвата (`WfpBlocker` без драйвера + `Redirector` за интерфейсом) и сам интерфейс `Redirector`.
> **Что отменено:** выбор бэкенда. По итогам [E1](../experiments/E1-windivert.md) исключён `windivert`, по итогам [E2](../experiments/E2-driver-signing.md) — `wfpcallout`. Реализаций у интерфейса ноль; T3 выполняется адаптивным поднятием TUN. См. ADR-007.
**Дата:** 2026-08-24
**Решает:** конфликт требования T3, RQ4, RQ11, риски R3, R13, R14, R15
**Заменяет:** §4.4 документа [01-analysis.md](../01-analysis.md)

## Контекст

Требование T3: правила по приложениям должны работать во **всех трёх** режимах. Заказчик подтвердил (Q3) готовность к драйверу режима ядра ради этого.

Исследование радикально изменило оценку цены этого решения:

**1. WFP расщепляется на две части с очень разной стоимостью.**

| Задача | Требует драйвера? |
|---|---|
| **Блокировать** трафик (permit/block по IP, порту, протоколу, приложению) | ❌ Нет — user-mode API `fwpuclnt.dll`: `FwpmEngineOpen` / `FwpmSubLayerAdd` / `FwpmFilterAdd` |
| **Перенаправлять** соединение на локальный прокси (`ALE_CONNECT_REDIRECT`) | ✅ Да — redirect есть действие `callout`, а callout регистрируется только kernel-mode драйвером |

Отсюда: kill-switch, IPv6-политика, блокировка стороннего DoH и блокировка QUIC — **всё без драйвера**. Правила по процессам в TUN-режиме sing-box умеет нативно (`process_name` / `process_path`) — тоже без драйвера. Драйвер остаётся нужен **ровно для одной функции**: правила по приложениям в не-TUN режимах.

**2. Windows изменил правила для драйверов в апреле 2026.** Доверие к legacy cross-signed драйверам снято по умолчанию на Windows 11 24H2/25H2/26H1 и Server 2025. Способ подписи официального WinDivert в документации не раскрыт, а FAQ упоминает только SPC из коммерческого УЦ — что есть описание именно cross-signing. Ошибка 577 «Windows cannot verify the digital signature» на WinDivert документирована. **Пригодность WinDivert не установлена** — это эксперимент E1.

**3. Прецедент:** Amnezia — авторы AmneziaWG, с ресурсами — на Windows реализовали split tunneling по IP в двух режимах, а по приложениям только в одном, и даже это работает не всегда ([issue #2615](https://github.com/amnezia-vpn/amnezia-client/issues/2615)). Задача объективно тяжёлая.

## Решение

**Перехват строится в два слоя, а редиректор абстрагируется за интерфейсом со сменными бэкендами.**

### Слой 1 — `WfpBlocker` (обязательный, без драйвера)

User-mode WFP-фильтры через `fwpuclnt.dll`. Активен во всех трёх режимах. Отвечает за:
- kill-switch (`onAllDown = block`),
- политику IPv6,
- блокировку стороннего DoH,
- блокировку QUIC/HTTP3,
- защиту от утечек в окне переключения failover.

### Слой 2 — `Redirector` (опциональный, требует драйвера)

Интерфейс в слое Platform:

```go
type Redirector interface {
    Available() (bool, Reason)          // доступен ли бэкенд на этой машине
    Start(cfg RedirectConfig) error     // цели: список процессов → адрес локального inbound
    Update(cfg RedirectConfig) error    // горячее обновление без разрыва
    Stop() error
    Events() <-chan RedirectEvent       // диагностика, счётчики, отказы
}
```

Два бэкенда за одним интерфейсом:
- ~~**`windivert`**~~ — ❌ **исключён по итогам [E1](../experiments/E1-windivert.md)**, см. ниже
- ✅ **`wfpcallout`** — собственный WFP-калаут на `FWPM_LAYER_ALE_CONNECT_REDIRECT_V4/V6`, attestation-подпись через Partner Center. **Единственный бэкенд.**

### Результат E1 (2026-08-24) — вариант `windivert` исключён

Анализ подписи `WinDivert64.sys` из официального релиза v2.2.2 показал:

| Проверка | Результат |
|---|---|
| Attestation-подпись Microsoft | ❌ Отсутствует |
| Cross-сертификат к `Microsoft Code Verification Root` | ❌ Отсутствует |
| Сертификатов Microsoft в подписи (всего вложено 6) | ❌ **Ни одного** |
| Подписант | `成都密思听科技有限公司` (Chengdu Misi Ting Technology Co., Ltd.) — **посторонняя проекту организация** |
| Издатель | Sectigo Public Code Signing CA EV R36 (коммерческий УЦ) |
| Срок действия сертификата | 2022-05-25 .. **2023-05-26 — истёк** |
| Почему подпись считается валидной | Только благодаря метке времени |

Истёкший сертификат плюс валидная метка времени — это **ровно та конфигурация**, против которой направлена политика апреля 2026. Плюс независимый довод: kernel-mode драйвер в VPN-продукте, подписанный посторонней организацией сертификатом трёхлетней давности, неприемлем вне зависимости от того, загрузится он технически.

Абстракция `Redirector` при этом полностью оправдала себя: реализовавшийся риск R15 меняет одну реализацию, а не архитектуру. Разработка не остановлена.

Тест фактической загрузки (E1-b) отменён как не способный изменить вывод.

**Если `Redirector` недоступен** (бэкенд не установлен, драйвер не загрузился, пользователь выключил) — приложение продолжает работать: правила по процессам действуют в TUN-режиме, а в лёгких режимах UI **явно** показывает, что они неактивны, и предлагает переключиться в полный туннель.

## Рассмотренные варианты

### A. Только WinDivert

| Измерение | Оценка |
|---|---|
| Сложность | Низкая |
| Стоимость | Низкая |
| Риск | **Высокий** |
| Экспертиза команды | Не требуется |

**Плюсы:** драйвер писать не надо; готовый MIT-референс; поддержка TCP и UDP.
**Минусы:** ⚠️ пригодность не установлена (E1); легко детектируется (WFPExplorer, WinDivertTool); исторически используется вредоносным ПО → реакция антивирусов; **весь проект оказывается заложником одной внешней зависимости**.

### B. Только собственный WFP-калаут

| Измерение | Оценка |
|---|---|
| Сложность | **Высокая** |
| Стоимость | **Высокая** (EV-сертификат + Partner Center + тестовый контур) |
| Риск | Средний |
| Экспертиза команды | **Требуется разработка драйверов** |

**Плюсы:** штатный документированный механизм Microsoft; полный контроль; нет сторонних зависимостей; attestation-подпись, по данным исследования, сохраняет силу после апреля 2026.
**Минусы:** разработка с нуля; риск BSOD; отдельный цикл сборки и тестовая ВМ с kernel debugging; календарный лаг подписи блокирует релиз (R13).

### C. Абстракция с двумя бэкендами ✅

| Измерение | Оценка |
|---|---|
| Сложность | Средняя |
| Стоимость | Средняя |
| Риск | **Низкий** |
| Экспертиза команды | Требуется, но не сразу |

**Плюсы:** разработка стартует **немедленно**, не дожидаясь E1 — интерфейс фиксирован, бэкенд подставляется; провал E1 не переписывает архитектуру, а меняет одну реализацию; если E1 удался, начинаем с дешёвого WinDivert и разрабатываем свой калаут параллельно, без давления сроков; можно выбрать бэкенд под окружение пользователя.
**Минусы:** интерфейс приходится проектировать «вслепую» под два разных механизма; два кодовых пути на сопровождении, если оставим оба.

### D. Отказ от драйвера (вариант V1 Фазы 1)

**Плюсы:** минимум риска, работа без админ-прав в лёгких режимах.
**Минусы:** не выполняет T3. Отвергнуто решением Q3 заказчика.

## Анализ компромиссов

Ключевой компромисс — **стоимость абстракции против стоимости неопределённости**. Написать интерфейс с двумя реализациями дороже, чем одну. Но альтернатива — либо ждать E1 и остановить разработку, либо выбрать бэкенд наугад и рискнуть переписыванием.

Абстракция здесь стоит дёшево, потому что граница естественная: «дай список процессов → заверни их соединения на этот адрес». Оба механизма реализуют ровно этот контракт.

Второй компромисс — **признание, что T3 может оказаться частично невыполнимым**. Если E1 провалится и attestation окажется недоступен в разумные сроки, продукт всё равно выпускается: полный туннель даёт правила по приложениям без драйвера. Это деградация, а не отказ, и она честно отражена в UI.

## Последствия

**Становится проще:**
- Три из четырёх «драйверных» задач решаются в user-mode — экономия месяцев.
- Разработка не блокируется экспериментом E1.
- Провал WinDivert (R15) локализован в одном модуле.
- В TUN-режиме — полный функционал вообще без драйвера.

**Становится сложнее:**
- Два кодовых пути редиректа на сопровождении.
- Нужно проектировать интерфейс под два разных механизма сразу.
- UI обязан отражать состояние «Redirector доступен / недоступен» — иначе пользователь не поймёт, почему правила не работают.

**Что придётся пересмотреть:**
- Результат E1 определит, какой бэкенд идёт в первый релиз.
- Результат E2 (сроки подписи) может отложить `wfpcallout` за пределы MVP.
- Если оба пути окажутся нежизнеспособны — вернуться к заказчику с вариантом V3 (всегда TUN, режимы как пресеты политики).
